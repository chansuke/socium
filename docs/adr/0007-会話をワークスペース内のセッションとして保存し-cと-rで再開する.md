# 会話をワークスペース内のセッションとして保存し-cと-rで再開する

## Context and Problem Statement

socium はワークスペースごとに会話を一つだけ持ち、起動すると必ずそれを再開する（`.socium/conversation.json`）。別の作業を始めるには `/clear` で会話を消すしかなく、消した会話には戻れない。Claude Code と同じく、起動時は新しい会話を始め、`-c` で直前の会話を、`-r` で選んだ会話を再開したい。ADR 4 は Activity の記録を、named session（SOC-026）の実装時にセッションごとのファイルへ分けるとしていた。

## Decision Drivers

* 既存の会話を消さずに新しい形式へ移せ、移行が途中で止まっても失われない。
* 再開する会話を ID か一覧から選べる。
* 会話の保存（SOC-012 の原子的な snapshot）と Activity の記録（ADR 4）の仕組みを変えない。
* 同じワークスペースで二つの socium が同じファイルを書かない。

## Considered Options

* 会話ごとに `.socium/sessions/<ID>/` を作り、snapshot と Activity をそこへ置く。
* 一つの snapshot に複数の会話を入れる。
* 会話ごとに別の workspace state ディレクトリ（`.socium-<ID>/`）を作る。

## Decision Outcome

Chosen option: 「会話ごとに `.socium/sessions/<ID>/` を作る」。snapshot と Activity の保存処理をそのまま使え、会話を一つ消したり退避したりするのもディレクトリ単位で済むため。

* ID は会話を始めた時刻（UTC）の `YYYYMMDD-HHMMSS-xxxx`。`xxxx` は秒未満の時刻から取る。時刻順に並び、目で見て区別できる。`-r` は完全な ID か一意な接頭辞を受け付ける。
* フラグなしの起動は新しいセッションを始め、何かを保存するまでファイルを作らない。`-c` は保存時刻が最も新しく、メッセージのあるセッションを開く。無ければ新しいセッションを始めて警告する。`-r` は ID が無ければ一覧を表示して選ばせる。
* `/clear` は新しいセッションに切り替え、前のセッションのファイルには触れない。Activity の回転も行わない。
* `/resume` は turn の合間にだけ別のセッションへ切り替える。実行中は切り替えない。切り替え先に保存された `/model` の選択を適用し、そのモデルが起動できなければ今のモデルのまま thinking を外す（起動時と同じ扱い）。`-r` の一覧も起動後の TUI の中で同じものを出す。
* `/rename` で付けた名前は会話の snapshot に保存し、`-r`・`/resume` は ID、名前、ID の接頭辞の順に照合する。一覧で `d`・`y` と押すとセッションのディレクトリを完全に消す。開いているセッションは消せない。
* 会話欄は snapshot の message と turn の event から組み立て直す。tool の呼び出しは名前と主な引数、一行の結果、人が承認したか、を一項目にまとめ、失敗した turn はその turn の後に示す。実行中も同じ整形の項目を出すので、再開の前後で見た目が変わらない。
* 保存のたびに一覧用の `meta.json` を書く。snapshot のサイズと更新時刻が一致するときだけ使い、一致しなければ snapshot を読んで書き直す。書けなくても保存は失敗させない。
* 新しいセッションは、最後に保存されたセッションの `/model` の選択を引き継ぐ。
* ワークスペースのロックはこれまで通り一つ。同じワークスペースで同時に動くのは一つの socium だけとし、セッションごとのロックは設けない。edit history、入力履歴、command の出力はファイルの状態に結びつくので、ワークスペースに置いたままにする。
* 旧形式の `.socium/conversation.json` と `activity.jsonl`・`activity.1.jsonl` は、ロックを持った状態で、更新時刻から作った ID のセッションへ rename する。会話を最後に動かすので、途中で止まっても次の起動で続きから移せる。移行先に同名のファイルがあれば上書きせず起動を止める。

### Consequences

* Good, because 会話を消さずに別の作業を始め、あとで戻れる。
* Good, because ADR 4 の Activity の記録がセッション単位になり、再開した会話の Activity が表示される。
* Good, because 一覧は通常 `meta.json` だけを読み、大きな snapshot を毎回解析しない。
* Bad, because 保存のたびに `meta.json` の書き込み（sync を含む）が一回増える。
* Bad, because 一覧で消したセッションは戻せない。
* Bad, because 再開できるのは同じワークスペース内のセッションだけ。

### Confirmation

core の単体テストで、ID の形式、移行（途中で止まった場合と衝突する場合を含む）、一覧の並びと除外、ID・名前・接頭辞の解決、新規・継続・指定再開・`/clear` の挙動、新規セッションへのモデルの引き継ぎ、`/resume` での切り替えとモデルの適用、削除の拒否条件、`meta.json` の利用と再生成、会話欄の組み立て直しと実行中の表示の一致を確認する。TUI の単体テストで、フラグの解析と一覧の操作・削除の確認・表示を確認する。

## Pros and Cons of the Options

### セッションごとのディレクトリ

* Good, because 保存の単位と境界が今と同じ。
* Bad, because 一覧を作るのにディレクトリを走査する。

### 一つの snapshot に複数の会話

* Good, because ファイルが増えない。
* Bad, because 一つの会話を保存するたびに全会話を書き直し、64 MiB の上限も共有する。

### 会話ごとの state ディレクトリ

* Good, because 会話ごとに完全に分かれる。
* Bad, because edit history やロックまで分かれ、同じファイルへの編集の取り消しが会話をまたいで壊れる。

## More Information

ADR 4 の「SOC-026 で session ごとのファイルに分ける」をこの ADR で実施した。SOC-026 の範囲（複数セッション、tool 履歴の表示、切り替え）もこの ADR で扱う。
