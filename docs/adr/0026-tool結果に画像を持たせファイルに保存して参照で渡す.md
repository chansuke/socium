# tool結果に画像を持たせファイルに保存して参照で渡す

## Context and Problem Statement

tool の結果は文字列 1 つである。会話の履歴、セッションの記録、クライアントへ送るメッセージと承認の要求も、文字列だけを持つ。

ブラウザの操作 ([ADR 27](0027-起動中のchromeにcdpで接続しoriginごとの承認でブラウザを操作する.md)) とデスクトップの操作 ([ADR 28](0028-デスクトップ操作をホスト上の有効化とアプリ単位の許可に限って認める.md)) は、スクリーンショットをモデルへ返す。web とモバイルのクライアント ([docs/clients.md](../clients.md)) の利用者は、ホストの画面を見られないので、承認の判断にも同じ画像が要る。

画像を tool の結果、履歴、記録、クライアントとのやり取りでどう持つかを決める。

## Decision Drivers

* 保存済みのセッションを、変換なしに読める。
* セッションの記録と、クライアントへ送る状態が、画像の分だけ膨らまない。
* 画像を読めないモデルに、画像を送らない。
* スクリーンショットには利用者の画面が写る。コマンドやファイル用の tool から読めない場所に置く。

## Considered Options

* 画像を base64 の文字列として、今の文字列の結果に埋める
* 結果を文字と画像の並びにし、画像の中身を履歴にそのまま持つ
* 結果を文字と画像の並びにし、画像はファイルに保存して履歴には参照だけを持つ

## Decision Outcome

Chosen option: 「結果を文字と画像の並びにし、画像はファイルに保存して履歴には参照だけを持つ」。記録と通信の大きさが画像の枚数に比例しなくなり、モデルごとに送る枚数を選べるため。

* tool の結果は「文字列」または「文字と画像の並び」とする。保存済みの記録にある文字列は、そのまま読む。
* 画像は `.socium` の下に、セッションごとのディレクトリを作って保存する。履歴が持つのは、ファイルの場所、形式、縦横の大きさである。`.socium` は子プロセスから隠してあり、ファイル用の tool も読めない。
* プロバイダへ送る要求を組み立てるときに、ファイルを読んでその形式に合わせる。
  * Anthropic の接続形式では、tool の結果の中に画像を置く。
  * OpenAI Responses の組み込みのデスクトップ操作では、専用の出力にスクリーンショットを置く。
  * tool の結果に画像を置けない接続形式では、結果には文字だけを置き、直後の利用者メッセージに画像を置く。
* `models.toml` の `features` に `vision` を足す。`vision` のないモデルには画像を返す tool を出さない。
* 送る画像は新しいものから数えて一定の枚数までとし、それより古い画像は「画像を省いた」ことを示す文に置き換える。圧縮のモデルには画像を送らない。
* クライアントへ送るメッセージと承認の要求は、画像の参照を持てる。ゲートウェイは認証した相手にだけ画像を返し、モバイルには縮小した画像を返す。
* セッションを消すときに、その画像も消す。

### Consequences

* Good, because 保存済みのセッションがそのまま読める。
* Good, because 記録、圧縮の入力、クライアントへの状態に、画像の中身が入らない。
* Good, because 遠隔の利用者がモデルと同じ画像を見て承認を判断できる。
* Bad, because 履歴がファイルを指すので、ファイルが消えると、その画像は再開後に送れない。その場合は、省いたことを示す文に置き換える。
* Bad, because 画像は文字よりも多くのトークンを使う。送る枚数の上限は、コンテキストウィンドウの扱い ([ADR 15](0015-組み込みモデルの窓を実値にしtool結果に上限を設けて窓が埋まったら縮めて圧縮する.md)) と合わせて決める必要がある。

### Confirmation

型のテストで、文字列だけの保存済みの結果が読めること、文字と画像の並びが書いて読んで一致することを確かめる。プロバイダごとのテストで、要求の中の画像の位置が接続形式に合うこと、`vision` のないモデルの要求に画像と画像を返す tool が入らないこと、上限を超えた古い画像が文に置き換わることを確かめる。セキュリティのテストで、コマンドとファイル用の tool が画像のディレクトリを読めないことを確かめる。ゲートウェイのテストで、認証のない要求に画像を返さないことを確かめる。

## Pros and Cons of the Options

### 画像を base64 の文字列として結果に埋める

* Good, because 型を変えずに済む。
* Bad, because プロバイダは文字として受け取るので、モデルは画像として読めない。記録と圧縮の入力も、その分だけ大きくなる。

### 結果を文字と画像の並びにし、中身を履歴に持つ

* Good, because 履歴だけで要求を組み立てられ、ファイルとの対応を管理しなくてよい。
* Bad, because セッションの記録と、クライアントへ送る状態に、画像の中身が毎回入る。

### 結果を文字と画像の並びにし、画像はファイルに保存する

* Good, because 送る枚数と大きさを、要求を組み立てるときに選べる。
* Neutral, because セッションの削除と画像の削除を、合わせて行う必要がある。

## More Information

Anthropic の tool の結果に画像を置く形は、[computer use tool の文書](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool) で確かめた。OpenAI Responses の専用の出力は、[Computer use の文書](https://developers.openai.com/api/docs/guides/tools-computer-use) で確かめた。OpenAI の通常の関数の結果と、Chat Completions の tool メッセージが画像を受け取れるかは未確認である。受け取れると確かめるまでは、直後の利用者メッセージに置く。
