# SOC-049: 公開してはいけないコミットの情報を入れない

GitHub: なし (2026-11-19 の公開前レビューで発見)

## 問題
2026-11-15 に履歴を書き換えて、セッション URL と個人のメールアドレスを消した。その翌日に、セッション URL 入りのコミット 16 件と、作者が個人のメールアドレスのコミット 2 件が main に入った。書き換えだけでは、同じものがまた入るのを止められない。

## 対応・受け入れ条件
- `scripts/check-commit-metadata.sh` が、Claude Code のセッション URL と `Claude-Session:` 行を含むコミットメッセージと、作者かコミッターが `chansuke` で noreply 以外のアドレスのコミットを拒む。個人のアドレスはスクリプトに書かない。
- pre-commit の commit-msg フックで、コミットする前に確かめる。
- Commit metadata ワークフローで、PR のコミットと、main への push を確かめる。merge や squash のコミットは GitHub が PR のタイトルと本文から作るので、マージした後にしか確かめられない。
- 範囲やメッセージのファイルが読めないときは、通さずにエラーにする。
- URL は大文字小文字を区別せずに探す。
- main への push の検査は、次の push で取り消さない。次の push は自分のコミットしか確かめないため。
- PR はスクリプトそのものも書き換えられるので、スクリプトと試験の変更は Checker changes ワークフローで人が確かめる対象にする。
- PR のタイトルと本文は検査しない。merge と squash を許すと、それがコミットになる。main への push の検査は公開の後でしか気づけない。どちらも、公開のときに rebase merge だけを許し、main への直接の push を禁じ、このワークフローを必須にする ruleset で塞ぐ ([公開の手順](../public-release-review.md))。
- アドレスにタブを入れて検査を避けることはできるが、このスクリプトは手違いを止めるためのもので、自分の検査を避けようとする人は相手にしない。

2026-11-19 完了。
